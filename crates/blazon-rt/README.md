# blazon-rt

Runtime support for bindings generated by `blazon`, and for consumers that host
a JVM.

- `Jvm::start(libjvm, options)`: `dlopen`s a `libjvm` chosen at runtime, creates
  the JVM through `JNI_CreateJavaVM` and registers it for the process.
- `vm::env()`, `vm::scope(capacity, f)`: the calling thread's `JNIEnv`
  (attached on first use) and a local reference frame.
- Handles: `Handle`, `IsA<T>`, `HandleExt` (`upcast`, `downcast`), `Global<T>`
  with `Rebind` for cross-thread storage. A handle owns one local reference and
  releases it when dropped.
- `Error` / `Result`: a Java exception is `Error::exception()` (class, message,
  trace) and the error's `source()`; `Display` shows the exception line and its
  first frame.
- `member`: cached class references, method, field and constructor IDs, which
  every generated call goes through. `reflect`: the same for members that are
  not public, through `java.lang.reflect`.
- `conv`: the conversions generated code applies to arguments and results.
- `java`: typed handles for the standard Java types (`Object`, `Class`,
  `String`, the boxed numbers, `Iterable`, `Iterator`, `Collection`, `List`,
  `Set`, `Map`, `Optional`, `UUID`, `Throwable`, `Runnable`, `OutputStream`,
  `ByteArrayOutputStream`, `BigInteger`, `Duration`) with the Rust traits that
  fit: `IntoIterator`, `Iterator`, `FromIterator`, `Extend`, `Ord`, `Display`.
  Generics are erased at run time, so an element type is a promise the caller
  makes.

Nothing here knows about Bazel or Starlark.
